
# Mobile UI findings — 390px baseline

The 390px contact sheet covered all 15 routes. The shared header is visually consistent and the image-first art direction remains strong. The fixed bottom action bar is visible on every page and appears separated from the main hero content.

Amenities mobile has a strong hero composition, but the large headline occupies most of the first screen and the CTA sits close to the lower image boundary. The image mosaic is visually impactful but its split columns produce a hard vertical seam and the first viewport does not immediately communicate whether the CTA opens a gallery, directory or page section.

Availability and Leasing keep the large hero image and route CTA readable, but the fixed bottom bar creates a third competing action alongside the hero CTA and the header hamburger. This needs a clear primary-action rule on mobile.

Space invalid and Privacy are intentionally text-led rather than image-led; their mobile density is acceptable, but the fixed bottom bar should be reviewed because it is less relevant to a privacy/error task.

Availability mobile shows a strong and legible hero, but the first content section begins immediately below it with a very large light-gray heading. The visual weight is acceptable for the editorial direction, although the fixed CTA bar should remain the sole persistent action layer and hero CTA language should not compete with it.

Location mobile has a clear hierarchy and an effective image crop. Its metadata block wraps across two lines in a controlled way. The main risk is global rather than page-specific: CTA bars and top navigation must remain safe at 320px, and all hero copy must tolerate text enlargement without clipping.

Resources mobile keeps the hero message readable, but it presents two prominent hero actions plus the persistent bottom bar, creating four visible actions in the first viewport. Visit has the same issue: Plan your arrival, Get directions, Find a Space and Book a Viewing all compete for attention. The fix should not remove capabilities; it should establish one primary action in the hero and reserve the fixed bar for the global conversion action.

A 320px pass was run on Home, Amenities, Availability, Leasing, Location, Resources and Visit. Home and Leasing remain usable at the narrow viewport: hero type wraps without clipping, statistics stay inside the image, and the fixed action bar fits within the viewport. The primary remaining concern is density rather than breakage: Leasing places hero CTA, three stats and contact details in one tall first screen, while the persistent bar adds another action layer. No horizontal overflow was observed in the screenshots.

## Implemented fixes

The shared UI/UX v2 layer now clips accidental horizontal overflow at the document level, allows headings and labels to wrap safely, makes tablists horizontally scrollable when needed, respects safe-area padding on the fixed mobile action bar, and reduces typography pressure at 320px. The fixed action bar is removed from Privacy and 404 because it is not relevant to those tasks.

The legacy `mobile-leasing-cta` generated by `capital-upgrade.js` is disabled on v2 pages so there cannot be two competing fixed bars. On narrow screens, hero action groups are stacked into a single column for safer touch targets. A fresh 390px screenshot pass covered all 15 routes, and a 320px pass covered Home, Amenities, Availability, Leasing, Location, Resources and Visit.

Final automated checks passed: all JavaScript files parse, all 15 HTML routes respond over HTTP, `git diff --check` passes, and the static audit reports zero missing alt attributes, zero missing image dimensions, zero buttons without explicit type and zero duplicate IDs.
